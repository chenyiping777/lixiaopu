# 商城静态页面与接口联调

## ChestnutShopWX（8080）接口联调区

在现有 8081 商城页顶部点击「8080 接口联调」，或直接打开 <http://localhost:8081/legacy/index.html>。这一组页面依据 `D:/github/project1/ChestnutShopWX/docs/接口请求示例.md` 整理了 78 个请求，分为账户与资料、商品与收藏、商品评价、地址与购物车、订单与支付、首页内容、客服与反馈、运营管理。它们调用 **ChestnutShopWX 的 8080 接口**，不表示 `lixiaopu` 的 8081 后端已实现同名功能。

启动两个服务后，在「联调设置」保持默认 API 地址 `http://localhost:8080`。该服务需要允许来自 `http://localhost:8081` 的跨域请求。登录成功后页面会把 `accessToken` 和 `refreshToken` 存在当前标签页；8080 项目的 `Authorization` 请求头直接使用访问令牌，不添加 `Bearer ` 前缀。示例中的账号、ID、图片等均须改成本地测试值。

写入请求默认锁定，需在设置中开启后才能提交；页面不会自动重试。每项请求可编辑路径、查询参数、JSON 请求体，并展示 HTTP 状态、耗时及脱敏响应。文档中的第 58 项需要 GET 请求体，浏览器 `fetch` 无法发送，页面明确提示使用 HTTP 客户端。重新生成请求目录可运行：`python docs/build-legacy-api-catalog.py D:/github/project1/ChestnutShopWX/docs/接口请求示例.md src/main/resources/static/legacy/api-catalog.js`。

## lixiaopu（8081）商城页

从项目根目录启动 `src/main/java/com/lixiaopu/LixiaopuApplication.java` 后，打开 <http://localhost:8081/>。页面放在 `src/main/resources/static`，由 Spring Boot 直接提供，无需安装前端依赖。请通过服务地址访问，不要双击 HTML 用 `file://` 打开。管理端使用同一个 Maven 工程中的 `src/main/java/com/lixiaopu/AdminApplication.java`，默认端口为 8082。

页面包括首页、全部商品、登录注册、收货地址、购物车、我的订单。首页和商品页会自动读取商品接口；其余页面通过按钮提交请求。页面底部的「请求与响应」面板展示 URL、方法、请求体、HTTP 状态、耗时和响应。密码、令牌、验证码等字段在调试面板中隐藏。

「联调设置」中可填写 API 服务地址；留空时与页面同源。切换地址会清除当前令牌。若使用跨域地址，需要后端配置对应 CORS 来源。示例预览是只读的，不向后端发送请求，方便先看页面样式。

## 当前后端已实现

| 页面操作 | 方法与路径 | 请求或响应说明 |
| --- | --- | --- |
| 首页推荐、全部商品 | `POST /api/products/search` | 请求 `{ "pageNo":1, "pageSize":12 }`；响应 `data.list`、`data.total`、`data.pages` |
| 分类商品 | `POST /api/products/by-category` | 请求包含 `categoryId`、`pageNo`、`pageSize`，可选 `sortBy`（`price` / `createTime`）和 `asc` |
| 商品详情 | `GET /api/products/{id}` | 响应商品详情，页面优先使用 `coverImage` |
| 注册验证码 | `POST /api/auth/sms` | `{ "phone":"13800000000", "purpose":"REGISTER" }`；本地测试可能返回 `localTestCode` |
| 买家注册 | `POST /api/auth/register` | `username`、`password`、`phone`、`code` |
| 密码登录 | `POST /api/auth/login` | `phone`、`password`；返回 `token`、`refreshToken` 等 |
| 微信登录 | `POST /api/auth/wechat` | 使用小程序 `wx.login` 取得的临时 `code` |
| 刷新令牌 | `POST /api/auth/refresh` | 请求 `refreshToken`；成功后旧刷新令牌失效 |
| 退出登录 | `POST /api/auth/logout` | 携带 Bearer 访问令牌 |
| 个人资料查询与修改 | `GET /api/user/detail`、`PUT /api/user/detail/update` | 修改字段：`nickname`、`phone`、`avatar`，携带 Bearer 令牌 |

后端统一响应为 `{ "success":true, "code":200, "message":"操作成功", "data":... }`。业务错误时 `success=false`，页面会显示 `code` 和 `message`。分类查询支持排序，`/search` 支持关键词筛选和分页；搜索排序过滤尚未实现。

登录令牌和刷新令牌存在当前标签页的 `sessionStorage`，页面不保存密码。Java `Long` ID 建议由后端序列化成字符串，避免浏览器丢失大整数精度。

## 静态页面尚未对齐的接口

以下入口已放进静态页面。地址和购物车已有 Controller，但当前路径分别是 `/api/address/...` 和 `/api/cart/...`，与下表静态页面请求的路径不同；订单接口也需继续实现。真实模式下返回 404 时，可用调试面板核对请求，再对齐页面和后端路由。

| 页面操作 | 方法与路径 | 请求 |
| --- | --- | --- |
| 查询、新增地址 | `GET /api/addresses`、`POST /api/addresses` | 地址字段：`receiverName`、`receiverPhone`、`province`、`city`、`district`、`detailAddress`、`isDefault` |
| 查询、加入购物车 | `GET /api/cart/items`、`POST /api/cart/items` | 加入：`{ "productId":"1", "quantity":1 }` |
| 更新、删除购物车条目 | `PATCH /api/cart/items/{id}`、`DELETE /api/cart/items/{id}` | 更新：`{ "quantity":2 }` |
| 提交订单 | `POST /api/orders` | `{ "addressId":"1", "cartItemIds":["1"], "remark":"" }` |
| 查询订单列表、详情 | `GET /api/orders`、`GET /api/orders/{id}` | 详情应包含 `items` 明细 |

列表 `data` 可以直接是数组，或使用 `data.list` / `data.records`。购物车勾选仅用于本次提交，不自动保存。订单金额由后端根据商品实际价格计算，前端不提交金额；订单、地址和购物车数据均需根据已验证的令牌检查归属。

推荐联调顺序：商品列表与详情 → 注册登录 → 地址 → 购物车 → 下单与订单查询。首次实现每个接口后，分别检查正常请求、未登录、无权限、商品不存在和库存不足等情况。
