# 栗小铺项目 Java 注解说明

> 扫描范围：`D:\github\project1\lixiaopu` 的 `shop-common`、`shop-user`、`shop-admin` 三个模块，含 `src/main/java` 和 `src/test/java`。依据当前源码和根 `pom.xml` 整理。这里的“来源”指注解的**完整包名及所属依赖**；“项目用法”指本仓库实际使用处，而不是框架所有可能的功能。

## 1. 先看注解在项目中的工作链

以用户注册为例：`@SpringBootApplication` 启动并扫描 Bean → `@RestController` 暴露 Controller → `@RequestMapping` 与 `@PostMapping` 组成 URL → `@RequestBody` 把 JSON 转成 DTO → `@Valid` 触发 DTO 上的 `@NotBlank`、`@Pattern` → `@Service` 中的 `@Transactional` 保证注册和角色绑定处于一个事务 → `@RestControllerAdvice` 与 `@ExceptionHandler` 把异常转为统一响应。

商品查询的另一条链：`@MapperScan` 注册 Mapper → MyBatis Plus 的 `@TableName`、`@TableId`、`@TableField` 建立实体与表字段的映射 → `@JsonFormat` 等 Jackson 注解决定 HTTP JSON 的外观。

项目依赖来源：Spring Boot `3.5.16`（Spring Web、容器、校验、事务、测试）；MyBatis Plus `3.5.17`；Lombok；Jackson；Jakarta Validation；JDK `17`。具体坐标见根 `pom.xml` 及三个子模块 `pom.xml`。

## 2. Spring Boot 与 Bean 容器

| 注解 | 来源 | 作用与本项目用法 |
| --- | --- | --- |
| `@SpringBootApplication` | `org.springframework.boot.autoconfigure.SpringBootApplication`，Spring Boot | 标记启动类，组合了自动配置、组件扫描等功能。`shop-user/.../LixiaopuApplication.java` 启动用户端；`shop-admin/.../AdminApplication.java` 用 `scanBasePackages="com.lixiaopu"` 扫描公共包。 |
| `@MapperScan` | `org.mybatis.spring.annotation.MapperScan`，MyBatis Spring（由 MyBatis Plus starter 引入） | 扫描 `com.lixiaopu.mapper` 下的 Mapper 接口并注册代理。两个启动类都有它，因此这些接口不必逐个写 `@Mapper`。 |
| `@Component` | `org.springframework.stereotype.Component`，Spring Context | 把普通类注册为 Spring Bean。用于 `AuthFilter`、`JwtUtil`、短信/微信网关、配置属性类等。 |
| `@Service` | `org.springframework.stereotype.Service`，Spring Context | `@Component` 的业务层语义形式；用于 `AuthService`、`ProductServiceImpl`、`UserServiceImpl` 等实现类，以便依赖注入和代理增强。 |
| `@Configuration` | `org.springframework.context.annotation.Configuration`，Spring Context | 声明配置类。`MybatisPlusConfig` 注册分页拦截器；`ShiroAuthConfig` 注册认证相关 Bean。 |
| `@Bean` | `org.springframework.context.annotation.Bean`，Spring Context | 将方法返回对象注册为 Bean，适合不能直接改源码的第三方类。项目在 `MybatisPlusConfig` 中注册 `MybatisPlusInterceptor`，在 `ShiroAuthConfig` 中注册 Shiro 对象。 |
| `@Autowired` | `org.springframework.beans.factory.annotation.Autowired`，Spring Beans | 从容器注入依赖。Controller、Service、`AuthRealm` 等处使用字段注入；新代码也可考虑构造器注入，便于测试和保证必需依赖。 |
| `@ConfigurationProperties(prefix=...)` | `org.springframework.boot.context.properties.ConfigurationProperties`，Spring Boot | 将同前缀配置批量绑定到对象。`AuthProperties` 绑定 `lixiaopu.auth`；`AliyunOSSProperties` 绑定 `aliyun.oss`。两类还用 `@Component` 注册 Bean。 |
| `@Value("${...:}")` | `org.springframework.beans.factory.annotation.Value`，Spring Beans | 注入单个配置值，冒号后的空串是缺省值。用于短信、微信网关及管理员首次初始化配置。与 `@ConfigurationProperties` 的批量绑定场景不同。 |
| `@Profile` | `org.springframework.context.annotation.Profile`，Spring Context | 按激活的 profile 决定是否注册 Bean。`local-test` 使用本地短信/微信网关；`!local-test` 使用 HTTP 短信和真实微信网关。未激活 `local-test` 时会选后者，须配置对应外部服务才能完成相关调用。 |
| `@Transactional` | `org.springframework.transaction.annotation.Transactional`，Spring Tx | 在 Spring 代理调用业务方法时开启事务；项目用于 `AuthService.register`、`wechat`、`createAdmin`、`bootstrapAdmin`。`resetPassword`、`changePassword` 当前没有标注它。默认对运行时异常回滚；同类内部直接调用方法通常不会经过事务代理。 |

### 对照示例

```java
@Configuration
public class MybatisPlusConfig {
    @Bean
    public MybatisPlusInterceptor mybatisPlusInterceptor() { /* ... */ }
}
```

这个配置里的 `@Bean` 注册的是**分页拦截器对象**；它与实体字段上的 `@TableField` 不属于同一类注解。

## 3. Spring MVC：HTTP 路由、入参与异常

这些注解主要来自 `spring-web` / `spring-webmvc`。

| 注解 | 完整来源 | 作用与本项目用法 |
| --- | --- | --- |
| `@RestController` | `org.springframework.web.bind.annotation.RestController` | 标记 REST 控制器；返回的 `Result` 会写成响应体。用于 `LoginController`、`ProductController` 和管理员 Controller。 |
| `@RequestMapping` | `org.springframework.web.bind.annotation.RequestMapping` | 声明通用路径前缀。`LoginController` 的 `/api/auth` 与方法上的 `/login` 拼成 `/api/auth/login`。 |
| `@GetMapping` | `org.springframework.web.bind.annotation.GetMapping` | 处理 GET。例：`ProductController` 的 `/{id}` 查询商品详情。 |
| `@PostMapping` | `org.springframework.web.bind.annotation.PostMapping` | 处理 POST。例：`ProductController` 的 `/search` 和 `LoginController` 的 `/register`。 |
| `@PutMapping` | `org.springframework.web.bind.annotation.PutMapping` | 处理 PUT。例：`UserController` 的 `/detail/update`。 |
| `@DeleteMapping` | `org.springframework.web.bind.annotation.DeleteMapping` | 处理 DELETE。例：`UserController` 的 `/collection/delete`。 |
| `@RequestBody` | `org.springframework.web.bind.annotation.RequestBody` | 从 HTTP 请求体读取 JSON 并反序列化为参数。例：`@RequestBody AuthDtos.Login`。它不会单独触发字段校验，需要结合 `@Valid`。 |
| `@PathVariable` | `org.springframework.web.bind.annotation.PathVariable` | 将 URL 模板变量绑定到方法参数。例：`/api/products/{id}` 的 `id`。 |
| `@RestControllerAdvice` | `org.springframework.web.bind.annotation.RestControllerAdvice` | 声明面向 Controller 的全局异常处理类，并以响应体形式返回数据。项目中是 `AuthErrorHandler`。 |
| `@ExceptionHandler` | `org.springframework.web.bind.annotation.ExceptionHandler` | 指定处理哪类异常。`AuthErrorHandler` 分别处理 `AuthException`、`MethodArgumentNotValidException`。 |

```java
@PostMapping("/register")
public Result register(@Valid @RequestBody AuthDtos.Register request) { /* ... */ }
```

`@Valid` 和 `@RequestBody` 作用不同：前者校验已绑定的对象，后者负责读入 JSON。注意 `UserController` 的 `@GetMapping("/collection/list")` 当前配了 `@RequestBody PageQuery`，这是**GET 请求体**，浏览器 `fetch` 无法发送；也没有 `@Valid` 来触发 `PageQuery` 的范围校验。此处是当前源码行为，不应把注解理解为已经完成这些能力。

## 4. Jakarta Validation：参数校验

这些注解由 `spring-boot-starter-validation` 引入；约束声明在 `AuthDtos` 与 `PageQuery`，触发点主要是 Controller 上的 `@Valid`，管理员初始化则显式调用 `Validator.validate(...)`。

| 注解 | 完整来源 | 作用与本项目用法 |
| --- | --- | --- |
| `@Valid` | `jakarta.validation.Valid` | 触发对象及其可级联属性的 Bean Validation。用户端和管理端认证 Controller 在 JSON DTO 参数上使用。 |
| `@NotBlank` | `jakarta.validation.constraints.NotBlank` | 字符串不能为 `null`、空串或全空白；用于手机号、密码、验证码等必填字段。 |
| `@Pattern` | `jakarta.validation.constraints.Pattern` | 用正则校验字符串。`AuthDtos` 用它约束手机号、用户名、密码字符范围、6 位验证码与短信用途。它本身不代替 `@NotBlank`。 |
| `@Min` | `jakarta.validation.constraints.Min` | 数值下限。`PageQuery.pageNo`、`pageSize` 都要求至少 1。 |
| `@Max` | `jakarta.validation.constraints.Max` | 数值上限。`PageQuery.pageSize` 至多 100。 |

**注意**：`ProductController` 的 `@RequestBody ProductQuery` 当前没有 `@Valid`，因此继承自 `PageQuery` 的 `@Min/@Max` 不会仅因写在字段上就自动执行；若希望请求校验生效，需要在入口处触发验证。

## 5. MyBatis、MyBatis Plus：Mapper 与数据库字段

| 注解 | 完整来源 | 作用与本项目用法 |
| --- | --- | --- |
| `@TableName` | `com.baomidou.mybatisplus.annotation.TableName` | 显式指定实体对应的数据库表。如 `Product` → `product`、`SysUser` → `sys_user`。 |
| `@TableId` | `com.baomidou.mybatisplus.annotation.TableId` | 标记主键。项目大量使用 `type=IdType.AUTO`，表示主键由数据库自增产生。 |
| `@TableField` | `com.baomidou.mybatisplus.annotation.TableField` | 指定列名（如 `category_id`）、`exist=false` 排除非表字段，或用 `fill=FieldFill.INSERT/INSERT_UPDATE` 声明自动填充时机。**当前源码未找到 `MetaObjectHandler` 实现**，因此 `fill` 标记本身不保证时间字段被自动写入。 |
| `@EnumValue` | `com.baomidou.mybatisplus.annotation.EnumValue` | 指定枚举持久化到数据库时使用的值。`CommonStatus.number` 用整数 `1/0` 入库。 |
| `@Select` | `org.apache.ibatis.annotations.Select` | 在 Mapper 方法上直接写查询 SQL。`AuthMapper` 用它查询角色和权限。 |
| `@Insert` | `org.apache.ibatis.annotations.Insert` | 在 Mapper 方法上直接写插入 SQL。`AuthMapper.grantRole` 写入用户角色关系。 |
| `@Update` | `org.apache.ibatis.annotations.Update` | 在 Mapper 方法上直接写更新 SQL。`AuthMapper.replacePassword` 更新密码哈希及版本。 |
| `@Param` | `org.apache.ibatis.annotations.Param` | 给 Mapper 方法参数命名，以便 SQL 中通过 `#{uid}` 等引用；`AuthMapper` 的多参数方法使用。 |

```java
@TableName("product")
class Product {
    @TableId(type = IdType.AUTO) private Long id;
    @TableField(value = "category_id") private Long categoryId;
    @TableField(exist = false) private List<ProductSpec> specList;
}
```

`shop-common` 和 `shop-user` 中均存在映射 `collection` 表的 `Collection` 类；阅读源码时应先看包名，避免混淆。`@MapperScan` 扫描 Mapper 接口，`@TableName` 则描述实体映射，二者作用不同。

## 6. Jackson 与 Spring 日期转换：HTTP 数据外观

| 注解 | 完整来源 | 作用与本项目用法 |
| --- | --- | --- |
| `@JsonFormat` | `com.fasterxml.jackson.annotation.JsonFormat` | 指定 JSON 日期等值的格式；`Product.createTime`、`Address.createTime` 等处使用 `DatePatternConstants.DATE_TIME_FORM`。 |
| `@JsonSerialize` | `com.fasterxml.jackson.databind.annotation.JsonSerialize` | 指定序列化器（Java → JSON）。`Product` 的时间字段显式使用 `LocalDateTimeSerializer`。 |
| `@JsonDeserialize` | `com.fasterxml.jackson.databind.annotation.JsonDeserialize` | 指定反序列化器（JSON → Java）。`Product` 的时间字段显式使用 `LocalDateTimeDeserializer`。 |
| `@JsonValue` | `com.fasterxml.jackson.annotation.JsonValue` | 将枚举某个值作为 JSON 输出。`CommonStatus.value` 输出 `"active"/"inactive"`。 |
| `@JsonCreator` | `com.fasterxml.jackson.annotation.JsonCreator` | 指定 JSON → Java 的创建入口。`CommonStatus.fromValue(String)` 接收上述字符串。 |
| `@DateTimeFormat` | `org.springframework.format.annotation.DateTimeFormat`，Spring Context | Spring MVC 的日期文本绑定格式，主要面对查询/表单参数；它与 JSON 使用的 `@JsonFormat` 不是一回事。项目在实体时间字段上同时标注。 |

**同一个枚举有两套表示**：MyBatis Plus 的 `@EnumValue` 处理数据库值，Jackson 的 `@JsonValue/@JsonCreator` 处理 HTTP JSON。`CommonStatus` 的数据库值是 `1/0`，JSON 值是 `"active"/"inactive"`，不要混用。

## 7. Lombok：编译期生成代码

Lombok 在编译期处理这些注解，减少样板代码；查看实际方法时要意识到源码里可能没有手写出来。

| 注解 | 完整来源 | 作用与本项目用法 |
| --- | --- | --- |
| `@Data` | `lombok.Data` | 生成 getter、setter、`toString`、`equals/hashCode` 等；实体、DTO、VO、`Result` 广泛使用。 |
| `@Getter` | `lombok.Getter` | 只生成 getter；用于 `ProductQuery`、枚举、`ResultCode` 等。 |
| `@NoArgsConstructor` | `lombok.NoArgsConstructor` | 生成无参构造器；用于 DTO、VO 和部分实体。 |
| `@AllArgsConstructor` | `lombok.AllArgsConstructor` | 生成全参构造器；用于 DTO、VO、`UserInfo` 等。 |
| `@Builder` | `lombok.Builder` | 生成链式 Builder；`UserInfo.builder()...build()` 的来源。 |
| `@FieldNameConstants` | `lombok.experimental.FieldNameConstants` | 生成字段名常量，减少硬编码字符串；`Product`、`Category` 使用。它**不负责数据库表名映射**，后者由 `@TableName` 控制。 |
| `@Slf4j` | `lombok.extern.slf4j.Slf4j` | 生成名为 `log` 的 SLF4J Logger；`ToolController` 用 `log.info(...)` 记录上传，`CategoryController` 和 `AliyunOSSUtils` 也标注。 |

## 9. 容易误认的文字与使用边界

1. Mapper 文件 Javadoc 里的 `@Entity` 是**注释文字**，项目没有使用 JPA 的 `@Entity`。`@author`、`@param`、`@return`、`@description`、`@createDate` 等也是 Javadoc/注释标签，不是当前 Java 代码中的框架注解。
2. `@TableField(fill=...)` 需要 MyBatis Plus 的自动填充处理器配合；只看到注解不能断言时间会自动保存。
3. `@Valid` 只在被调用的校验入口上起作用。字段有 `@Min/@Max`，并不说明所有 Controller 已经启用校验。
4. `@Transactional` 对通过 Spring 代理进入的方法生效；直接在同一对象内部调用被标注方法可能绕过代理。
5. `@DateTimeFormat`、`@JsonFormat`、`@TableField` 分别面向请求文本绑定、JSON、数据库映射，虽写在同一字段上但互不替代。
