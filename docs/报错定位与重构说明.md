# 报错定位与重构说明

## 修错前的实际问题

| 位置 | 问题 | 影响 |
| --- | --- | --- |
| 原 `shop-user` 的 `CartController` | 引用了当时不存在的 `CartProductDTO`、`CartDTO` | Java 编译失败 |
| 原 `shop-user` 的 `UserController`、`CollectionService` / `CollectionServiceImpl` | 引用了已删除的 `PageQuery`、`PageVO`、`ProductService` | Java 编译失败 |
| 原 `shop-admin` 的 `CategoryController` | 引用了不存在的 `CategoryDTO` 和服务方法 | Java 编译失败 |
| 原 `shop-admin` 的 `ProductController` | 引用了不存在的 `SimpleProductVO`、`ProductDocument`、`esCopyMapper`，并把非泛型 `Result` 当成泛型使用 | Java 编译失败 |
| `AuthRealm.supports` | 错误地检查令牌类型，拒绝 `JwtAuthenticationToken` | 认证测试出现 `UnsupportedTokenException` |
| `AuthService.resetPassword` | Redis 未返回用户 ID 时直接调用 `isBlank()` | 密码重置测试出现 `NullPointerException` |
| 后续改动的购物车实现 | 缺少 `RedisConnector`、`RedisKeyGenerator`、`CartMapper` 方法，DTO / 实体字段类型也不一致 | 再次出现多项 Java 编译错误 |

以上是编译和单元测试中定位到的错误。原 Maven 关系是 `shop-user → shop-common`、`shop-admin → shop-common`，未发现模块依赖环；这些报错不能归因于 Maven 循环依赖。此前购物车代码中的 Aspect、Job、Service 调用关系也没有证明当前存在 Spring Bean 注入环。

## 工程结构

按本次要求，三个 Maven 模块合并为根目录一个 `pom.xml` 和一套 `src`。保留两个启动入口：`LixiaopuApplication` 使用 8081，`AdminApplication` 使用 8082；共享代码只保留一份。原模块目录已从主工程移出，修错前参考源码存放在 `backups/`。

“修错前”参考归档是在已有未提交改动和后续编辑的情况下尽力重建的，**不是逐字节的原始工作区快照**。需要核对某段代码的准确历史时，应结合 Git 历史和归档查看。

本次只验证了编译、单元测试和两个 JAR 的入口。运行环境没有可用的 MySQL / Redis 服务，因此未做实际启动与接口联调。现有商城静态页的部分地址、购物车请求路径与当前 Controller 不一致，访问这些功能仍可能得到 404；具体接口状态见 [页面联调约定](页面联调约定.md)。
