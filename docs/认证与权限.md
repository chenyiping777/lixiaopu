# 认证与权限

## 升级与配置

MySQL 8.0.16+、Redis 6.2+。现有库先备份，再检查 `sys_user.phone` 的重复非空值；处理重复值后运行 `docs/sql/04-auth-migration.sql` 的索引及角色改名语句，再运行 `src/main/resources/db/02-roles.sql`。迁移脚本是一次性脚本，不要重复执行索引语句。旧买家如没有角色，审查 `user_type` 后执行脚本末尾注释中的角色补齐语句。旧管理员角色链接随角色代码改名保留；管理员账号需逐个审查类型与角色。新库直接运行 `01-full-schema.sql` 和 `02-roles.sql`。角色种子可重复执行。

旧账号若 `password` 不是 BCrypt 散列，登录会被拒绝；请用短信重置流程或可信离线迁移设置新密码。服务不会明文比对或自动升级旧密码。新密码在请求 DTO 中统一校验为 8–72 位可打印 ASCII 字符，以对应 BCrypt 的 72 字节上限。

两端必须设置相同的 `LXP_JWT_SECRET`（至少 32 字节随机值）及相同的 Redis。还需设置 `DB_USER`、`DB_PASSWORD`、`REDIS_HOST`、`REDIS_PORT`。生产短信需按实际供应商协议调整 `HttpSmsGateway` 的请求/响应映射，设置 `LXP_SMS_ENDPOINT`（HTTPS）、`LXP_SMS_API_KEY`、`LXP_SMS_SIGN`、`LXP_SMS_TEMPLATE`。微信小程序设置 `WECHAT_APP_ID` 与 `WECHAT_APP_SECRET`，由服务端调用微信 `jscode2session` 换取 openid；不要向客户端暴露 AppSecret。

仅本地测试可启用 Spring profile `local-test`：短信发送响应含 `localTestCode`，微信 code 使用 `local:<稳定测试标识>`。这个 profile 不应部署到公开环境。正式微信与短信未在无凭据的环境联调。

首次初始化系统管理员：在管理端进程启动前临时设置 `LXP_BOOTSTRAP_USERNAME`、`LXP_BOOTSTRAP_PASSWORD`、`LXP_BOOTSTRAP_PHONE`，运行后立即移除。仅在没有任何 `SYS_ADMIN` 角色账号时创建。无公开创建系统管理员接口，无默认密码。

## 接口

所有受保护接口通过 `Authorization: Bearer <access token>` 传令牌。请求和响应沿用 `Result`。管理端前缀为 `/api/admin/auth`，用户端为 `/api/auth`。

| 操作 | 路径 | 请求字段 |
| --- | --- | --- |
| 短信 | `POST /sms` | `phone`, `purpose`：`REGISTER` 或 `RESET_PASSWORD`（管理端只允许重置） |
| 买家注册 | `POST /api/auth/register` | `username`, `password`, `phone`, `code` |
| 手机密码登录 | `POST /login` | `phone`, `password` |
| 小程序登录 | `POST /api/auth/wechat` | `code`（来自 `wx.login`） |
| 重置验证 | `POST /reset/verify` | `phone`, `code`；返回短时 ticket |
| 设置新密码 | `POST /reset/password` | `ticket`, `password`；不会创建登录会话 |
| 登录后改密 | `POST /change-password` | `oldPassword`, `newPassword`；全端下线 |
| 刷新 | `POST /refresh` | `refreshToken`；旧刷新令牌立即失效 |
| 退出 | `POST /logout` | 空请求体；删除当前会话 |

系统管理员可调用 `POST /api/admin/users/administrators` 创建普通管理员（字段 `username`, `password`, `phone`），以及 `POST /api/admin/users/{id}/disable` 禁用账号。普通管理员无这两项权限。用户端 `/api/user/**` 需 `BUYER` 与 `buyer:access`；管理端需 `SYS_ADMIN`/`ADMIN` 与 `admin:access`，管理操作另检查具体权限。

会话在 Redis 保存 7 天，访问令牌 15 分钟。JWT 由 Hutool 以 HS256 签发和校验；令牌只包含用户 ID、会话 ID、令牌类型、签发方和过期时间。由旧版 JJWT 签发且使用其他 HMAC 算法的存量令牌，升级后需要重新登录。验证码 5 分钟、最多 5 次尝试、同手机号同用途每分钟最多发送一次。重置 ticket 10 分钟且一次性。刷新、验证码消费、ticket 消费均使用 Redis 原子命令或 Lua。账号禁用在每个请求重新检查数据库状态。改密时数据库 `auth_version` 原子递增，会话保存版本并在每次请求比对，覆盖改密与登录交错的情况。Redis 会话索引通过过期分数清理，用户全端下线时一次删除索引内所有会话。
